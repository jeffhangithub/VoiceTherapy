# 心理支持语音 Agent：架构分析与实施计划

状态：设计阶段，尚未初始化应用或修改 Hermes / Obsidian 配置。

## 1. 目标

构建一个仅供个人使用的移动端语音工具：用户可以在开车、步行或离开电脑时，从手机与 AI 进行连续的普通话语音对话；AI 使用 Hermes Agent 作为推理与工具调用中枢，并能按需检索 Obsidian 中的心理咨询文字记录。

第一版必须优先解决已有 Discord Voice Channel 方案的两个问题：

1. 车内或移动环境中的语音识别准确度不足。
2. 用户说完后到 AI 开始说话的延迟过长，且不能自然打断。

## 3. Discord 方案延迟分析

Hermes 默认语音回合是串行流水线：

```text
等待静音结束 -> 保存/提交整段音频 -> STT -> Hermes Agent -> 完整或近完整 TTS -> Discord 播放
```

总延迟至少由以下部分相加：

- 语音活动检测的静音等待。
- Discord 音频收取、Opus 解码和回合切分。
- 整段语音识别。
- Hermes 模型首 token 与可能的工具调用。
- TTS 合成和格式转换。
- Discord 音频发送缓冲。

单独更换 LLM 无法消除这类延迟。新方案必须同时引入流式 STT、低延迟端点检测、Hermes 文本流、分句流式 TTS 和用户抢话取消。

## 4. 推荐架构

```text
手机 PWA（后续可封装原生 App）
  - 麦克风、AEC/NS/AGC
  - 播放队列
  - 用户抢话检测
  - 文本转写与引用界面
              |
              | WSS 流式音频与控制事件
              v
Voice Gateway
  - 身份认证与会话管理
  - VAD / endpointing
  - 流式 STT
  - Hermes SSE 客户端
  - 回答分句器与流式 TTS
  - cancel / barge-in / reconnect
              |
              | HTTPS + SSE，仅文本
              v
Hermes API Server
  - 咨询人格与对话规则
  - 最小工具白名单
  - 多轮会话状态
              |
              | 只读 MCP 工具调用
              v
Obsidian Retrieval Service
  - 允许目录白名单
  - Markdown 解析与增量索引
  - FTS/BM25 + 向量混合检索
  - 返回来源、日期、标题、片段位置
```

### 4.1 为什么把音频链路放在 Hermes 外部

- Hermes 专注于推理、会话和工具调用，不必承担手机音频协议与播放状态机。
- Voice Gateway 可以独立比较 STT/TTS 厂商，而不改变知识库与 Agent 逻辑。
- 用户一开口即可立即停止本地播放，并取消尚未使用的 TTS/Agent 工作。
- 可以分别记录 VAD、STT、Hermes 首 token 和 TTS 首音频延迟，从数据上定位瓶颈。

### 4.2 Hermes 接入方式

核查本机 Hermes v0.18.0 源码后，第一选择改为 Gateway 的 `/v1/runs` 接口：

- `POST /v1/runs` 立即返回 `run_id`。
- `GET /v1/runs/{run_id}/events` 通过 SSE 提供 `message.delta`、工具生命周期和最终状态。
- 用户抢话时调用 `POST /v1/runs/{run_id}/stop`，同时立即停止手机端播放。
- Voice Gateway 用稳定的 `session_id` 标识会话，并维护有界 `conversation_history`。
- Voice Gateway 按自然短句聚合文本增量，尽早提交 TTS。
- 不把 Hermes 的 API bearer key 下发到手机；手机只访问 Voice Gateway。
- Voice Gateway 使用独立的 Hermes profile，并只启用咨询所需工具。

Runs API 的停止是后端“尽力取消”：Hermes 会调用 `agent.interrupt()` 并取消异步包装任务，但正在执行器线程中的工作不保证瞬间结束。因此 400 ms 抢话指标由手机本地立即停播保证，后端 `/stop` 用于减少无用推理、工具调用和 TTS。

`/v1/responses` 保留为状态管理更方便的备选接口；直接嵌入 Hermes Python Library 只作为 API 合同确实不足时的后备方案，因为它会把应用生命周期和 Hermes 内部版本强耦合。

## 5. Obsidian 数据边界

### 5.1 初始允许范围

候选白名单：

1. `raw/咨询纪要/心理咨询录音文字稿`
2. `concepts/therapy`

必须由用户确认后才能读取正文和建立索引。默认不索引日记、工作记录或整个 Vault。

### 5.2 检索设计

- Markdown 按标题层级、说话人轮次和长度切块，而不是固定字符数盲切。
- 每个块保存 `relative_path`、标题、会谈日期、块序号和内容哈希。
- 使用关键词检索处理人名、专有词和具体事件；使用向量检索处理主题与语义相似性。
- 对合并候选进行重排，默认只给 Hermes 4–8 个短片段。
- Hermes 回答所依据的笔记必须可在手机文本界面查看。
- 文件只读；索引存放在项目数据目录，不写回 Vault。
- iCloud 文件未下载到本地时，索引器要报告并跳过，不能把占位文件当成空记录。

### 5.3 记忆分层

- 当前对话：Hermes 会话上下文。
- 长期偏好：经用户允许后写入专用 Hermes profile memory。
- 历史事实与咨询材料：Obsidian 是来源，不自动改写。
- 新会话摘要：第一版只保存在应用数据库；是否写回 Obsidian 另行授权。

## 6. 语音链路与基准测试

不能仅凭供应商宣传选择 STT/TTS。先收集一小组用户本人录音：

- 安静房间普通话。
- 车内怠速、城市道路和高速背景噪声。
- 中英混说、家人称呼、咨询师姓名及常见专有词。
- 短句、长段叙述、停顿和自我修正。

候选 STT 至少包括：

- 一个中文优化的云端流式 ASR。
- 一个国际云端流式 ASR。
- 本机 faster-whisper 作为隐私与成本基线。

候选 TTS 至少包括：

- 一个低首包延迟的中文云端 TTS。
- 一个自然度较高的中文云端 TTS。
- Edge 或本地 TTS 作为成本/离线基线。

每次测试记录：

- 字错误率与关键实体错误率。
- 端点检测耗时。
- STT partial、final 延迟。
- Hermes 首 token 延迟。
- TTS 首音频延迟。
- 从用户停止说话到 AI 第一段可听音频的总延迟。

## 7. 初始验收标准

以下是建议目标，不是尚未测试的性能承诺：

- 安静普通话关键实体准确率不低于 95%。
- 真实车内样本关键实体准确率不低于 90%。
- 说话结束到 AI 第一段可听音频：中位数小于 1.8 秒，P95 小于 3 秒。
- 用户开始抢话后 400 ms 内停止 AI 播放。
- 网络短暂中断后能重连，且不会重复播放已确认的语音段。
- 每个使用知识库的回答都有可见来源；无命中时明确说明没有查到。
- 原始音频默认不持久化。
- Hermes 与 Obsidian 凭据永不进入浏览器包、日志或 Git。

## 8. 心理健康安全边界

该工具定位为个人心理支持和自我反思伙伴，而不是持证心理治疗师或医疗设备。

- 不进行确定性诊断，不给出药物调整意见，不伪造专业资质。
- 对不确定的历史事实先检索，再明确区分“记录内容”和“当前推测”。
- 危机策略按用户所在地配置；检测到即时自伤、伤人或无法保证安全的表达时，优先确认眼前安全并引导联系当地紧急服务或可信任的人。
- 不使用单个关键词机械触发危机流程；保留上下文判断和误触后的正常恢复。
- 在驾驶模式下避免要求用户阅读、点击复杂界面或进行会分散注意力的练习。
- 允许用户查看、导出和删除应用生成的对话记录与摘要。
- 后续邀请专业心理咨询师审阅人格提示、边界话术和危机流程。

## 9. 分阶段实施

### 阶段 0：确认决策与基线

- 确认手机平台、主要网络环境与车载蓝牙使用方式。
- 确认允许的 Obsidian 目录。
- 确认云端 STT/TTS/LLM 的隐私边界。
- 确认在当前仓库做本地代码开发，还是使用妙搭云端生成。
- 备份 Hermes 配置，评估是否迁移配置版本 30 → 33。

退出条件：所有数据访问和开发路径选择明确。

### 阶段 1：Hermes 文本后端

- 创建隔离的咨询 profile。
- 启用带认证的本地 API Server。
- 建立最小工具集与人格/安全规则。
- 验证多轮状态、SSE 首 token、取消和错误恢复。

退出条件：本机文本对话可重复通过，且不会调用越权工具。

### 阶段 2：Obsidian 只读检索 MCP

- 实现增量 Markdown 索引。
- 实现关键词、向量和混合检索。
- 接入 Hermes MCP，仅开放检索与读取命中片段。
- 构建小型人工问题集评估召回率、引用正确性和幻觉。

退出条件：目标问题能找到正确记录，回答来源可回溯，Vault 无写入。

### 阶段 3：语音基准

- 建立可替换的 STT/TTS provider 接口。
- 用同一组真实样本比较准确率和延迟。
- 调整 VAD、停顿容忍、中英语言提示和自定义词表。

退出条件：选定一套主供应商和一套降级方案，达到或接近验收指标。

### 阶段 4：手机语音 MVP

- PWA 获取麦克风并通过 WSS 发送音频帧。
- 实现连续回合、partial transcript、流式播放、抢话、取消和重连。
- 显示会话文字、知识库引用、隐私状态和一键结束。

退出条件：同一 Wi-Fi 和移动网络下均可完成 15 分钟连续对话。

### 阶段 5：安全与部署

- 身份认证、TLS、速率限制、日志脱敏和数据保留策略。
- 危机转介、驾驶模式和异常降级。
- 先使用私有网络或受保护入口从手机访问，不直接暴露 Hermes API。
- 测试 iPhone/Android 的锁屏、后台、蓝牙和耳机行为。

退出条件：个人远程访问稳定，安全清单和恢复步骤验证通过。

### 阶段 6：是否原生化

如果 PWA 在锁屏、后台音频或车载蓝牙方面不满足要求，再封装或开发原生客户端；如果 PWA 已满足真实场景，不为技术形式而增加复杂度。
