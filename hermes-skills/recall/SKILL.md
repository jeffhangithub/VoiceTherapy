# recall — 心理咨询历史会谈检索

在咨询会话中，当 Jeff 提到过去某次会谈、某个反复出现的模式、或某段历史细节时，帮他**从 vault 里把那段记录找出来、精炼地引回来**。这是《本地 Hermes 心理咨询语音助手 v0.2》Phase 2 的核心交付。

**核心定位：recall 是只读检索器，不是写回器，也不是对话引擎。** 它只负责「把历史找出来、引出来」，不改变当前会话状态机，不落盘任何文件（写回归 `session-notes`）。

## 触发条件（10.3）

- Jeff 说「上次怎么处理的」「第 N 次」「又和我妈那样了」「之前不是聊过……」「那次……后来怎样了」等**指向历史/模式的引用**。
- 用户明确要「查一下之前」「翻翻记录」「帮我回忆」。
- `counselor` 在会话中检测到历史线索，交棒过来（见「与 counselor 的关系」）。

**不触发**：日常闲聊、当前事件的倾诉（属于 counselor / self-reflection 的探索，不是历史检索）、以及需要写回的场景（写回归 session-notes）。

## 角色与边界

- **只读**：recall 只读 `咨询/` 下的历史记录，**绝不写、绝不改、绝不新建任何文件**。唯一的输出是「检索结果」，以对话形式返回。
- **不诊断、不总结新结论**：recall 是「把当时记下的东西原样引出来」，不是重新分析或下新判断。
- **不改真人记录**：`type: human` 的文件（林老师会谈逐字稿、人工记录）同样只读，正文一字不改。
- **非医疗、非危机干预工具**：与 counselor 相同的三条固定声明成立（不诊断、不替代咨询师、危机只转介）。recall 若在检索中撞见危机相关记录，只如实引用，不展开。

首次运行若 `咨询/` 目录或相关文件不存在，直接如实告知「我这边没有找到记录 / 该文件还没建」，**不要创建目录或文件**。

## 会谈 frontmatter 字段（6.4）

每篇 AI 会谈笔记头部含以下字段，recall 靠它们做**元数据过滤**，而不是靠读全文：

```yaml
date: 2026-09-01      # 会谈日期（引用必带的依据）
type: AI              # AI | human（human 只读不写）
mode: driving         # driving | desk
focus: 本次焦点       # 一句话焦点
mood_start: …
mood_end: …
techniques: []
crisis: false
```

## 检索工作流（先定位，再搜，再读片段）

### 第 1 步：主题/模式定位（先过滤，别一上来读全文）

1. 从 Jeff 的话里**提取线索**：是人名？是关系（我妈/我爸/太太）？是情绪（焦虑/失眠/愤怒）？是模式（「又是这样」「又开始了」）？是编号（「第 N 次」）？
2. **读 `来访者/我/模式.md`**：看有没有已命名的模式能对上（例如「每次和母亲冲突后自责」这种长期模式）。
3. **搜 `主题/*.md`**：用 `search_files` 在 `咨询/主题/` 下按议题关键词找反向索引，命中后读那篇索引，拿到「相关会谈」链接列表。
4. 若主题索引还没有该议题，才退回直接 `search_files` 在 `咨询/来访者/我/会谈/` 里按 `focus`/正文关键词搜会谈文件。

### 第 2 步：按元数据过滤会谈（保持快，6.4）

- 用 `search_files(target='files')` 列 `会谈/` 下的文件名（`YYYY-MM-DD-AI-<标签>.md`），文件名自带日期。
- 需要看 frontmatter 时，**只读文件头部几行**（`read_file` 的 frontmatter 段），拿到 `date / type / focus / mode`，据此过滤，**不读整篇正文**。
- 若是「第 N 次」查询：把命中的会谈按 `date` 排序，数出第 N 篇是哪个日期。
- **禁止**把多篇会谈全文一次性打进上下文。只保留命中名单，然后进第 3 步。

### 第 3 步：读 1-2 个文件片段

- 从命中名单里挑**最相关的 1-2 篇**，只读其中的相关段落（例如「探索要点」「工作」「Takeaway」「写回」里对应的那几行），**不是整篇**。
- 引用上限：**最多引用 2-3 段**会谈片段。超过就砍，保留最贴今天议题的。

### 第 4 步：按固定结构输出

把检索结果组织成下面四段（见「输出结构」），返回给对话。driving 模式压缩成 4 句。

## 输出结构（10.3）

**默认（desk）输出四段：**

1. **当时发生了什么** — 原样转述记录里写的事实，不添油加醋。
2. **做了什么** — 当时命名的模式 / 尝试的句子 / 有效干预 / takeaway，如记录所述。
3. **与今天的连接** — 用一句话点出「今天说的这个，跟那天像不像」，**用问题或假设语气，不下结论**。
4. **一个问题** — 结尾抛一个具体的小问题，把球递回给 Jeff（例如「今天这个，和那天是同一个模式吗？」）。

**driving（开车）压缩版：4 句** — 每句一个功能：①当时发生 ②做了什么 ③与今天连接 ④一个问题。短句、不引长段、不让他做长阅读。

## 引用规则（硬约束）

- **引用必带日期**：例如「你 2026-08-24 那次提到……」。不带日期就不引用。
- **不编造未陈述的事实**：只引用记录里真实存在、且 Jeff 自己说过的东西。原文没有的，一个字都不加。
- **无记录时明确说明**：查不到就直说「我这边没有查到相关记录 / 该主题还没有索引」，**不虚构会谈、不脑补、不假装记得**。
- **区分「记录」与「我的推断」**：引用原文部分用「记录里写的是……」，推断部分用「从这些看，可能是……」，两者不混。

## 保持快的硬规则（6.4 重申）

- 先按 frontmatter 元数据过滤，再决定读哪 1-2 个文件片段。
- 读片段时用 `read_file` 的 `offset/limit` 只取相关段落，不整篇拉进上下文。
- 主题/议题反向索引由 `主题/*.md` 承担，recall 优先走索引，避免每次全目录扫正文。

## 只读边界（绝不写）

- recall **不写任何文件**：不新建、不覆盖、不追加、不删除 `咨询/` 下任何内容。
- 不要因为「查不到」就去创建主题索引或补档案——那是写回/维护职责（session-notes 或人工），不是 recall。
- 如果 Jeff 在检索过程中产生了新的觉察，**引导他回到当前会谈（counselor），由 session-notes 落盘**，recall 自己绝不顺手写。

## 与 counselor / session-notes 的关系

| 角色 | 职责 |
|---|---|
| counselor | 对话状态机（S0-S7），维护「本轮焦点/是否收束」两个布尔量；检测到历史线索时交棒 recall |
| **recall（本 skill）** | 只读检索历史，返回「当时发生→做了什么→与今天连接→一个问题」，**不改变会话状态机** |
| session-notes | 会谈结束写回（新建会谈笔记、更新热层），**唯一的写回方** |

- counselor 交棒过来时，recall 只做检索并返回结果，**不接管状态机、不推进 S 状态**。
- recall 返回后，把「球」交还给对话（counselor 继续），由它决定下一步。

## Pitfalls

- **路径带空格**：vault 路径含空格（`Mobile Documents`），`read_file`/`search_files` 直接传绝对路径即可，不要手工拼 shell 命令（shell 里必须加引号）。
- **别把 `主题/` 和 `模式.md` 混为一谈**：`模式.md` 是「反复的行为/情绪/关系模式」命名，`主题/*.md` 是「议题→会谈」反向索引。定位时两个都查，但用途不同。
- **frontmatter 里有 `type: human`**：命中 human 文件时只读不写（recall 本来就只读，但要意识到那是真人记录，转述时保持原样）。
- **「第 N 次」要先排序再数**：先按 `date` 排好命中的会谈，再取第 N 篇，别按文件名/目录列出顺序乱数。
- **别为了「有内容」而编**：查不到就说没查到，宁缺毋滥，虚构会谈是这条 skill 最不能犯的错。
