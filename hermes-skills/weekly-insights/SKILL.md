# weekly-insights — 心理咨询周洞察

在咨询系统的 Phase 4 里，把「本周的 AI 会谈」聚合成一份可回看的周洞察。这是《本地 Hermes 心理咨询语音助手 v0.2》的第 4 个 skill（§10.4），补全 counselor / session-notes / recall 之后的周级复盘能力。

**核心定位：weekly-insights 是只读聚合 + 只写自家 洞察/ 与轻量更新 模式.md 的周复盘器。** 它读本周 AI 会谈、提炼模式、落一份周洞察，把结论当成「假设」交给 Jeff 改，绝不写真人记录、不替 Jeff 下结论。

## 触发条件（10.4）

- Jeff 说「本周复盘」「这周怎么样」「帮我看看这周」「周报」
- 可选：cron 定时（如每周日晚，需设计运行时刻落在周一 00:00 之后、且与「当周会谈」的归周逻辑一致）

**不触发**：日常闲聊、单次会谈进行中、历史检索（recall）、会谈结束写回（session-notes）。

## 角色与边界

- **只读 AI 会谈 + 只写自家文件**：读 `咨询/来访者/我/会谈/` 下本周 `type: AI` 的会谈；只写 `咨询/洞察/YYYY-Wxx.md`（本周洞察）和 `咨询/来访者/我/模式.md`（轻量追加）。除此之外不新建、不覆盖、不删除任何文件。
- **结论 = 假设，不是定论**：所有从记录里提炼的模式、判断，都写成「我观察到……（可能是/像是）」，并明确标注「待你确认」。绝不把推断当事实写死。
- **不改真人记录**：`type: human` 文件（林老师会谈逐字稿、人工记录）只读不写，正文一字不改。
- **非医疗、非危机干预工具**：与 counselor 相同，不诊断、不替代咨询师、危机只转介。若本周会谈里撞见危机相关记录，只如实引用、不展开。

## 路径常量

```text
VAULT   = /Users/ironsoul/Library/Mobile Documents/iCloud~md~obsidian/Documents/Vaults/Jeff
咨询根   = <VAULT>/咨询/

来访者/我/会谈/            ← AI 会谈笔记（YYYY-MM-DD-AI-<标签>.md，含 date/type/focus/mode frontmatter）
来访者/我/模式.md          ← 长期反复模式（命名后的索引；本 skill 只做轻量追加，不覆盖）
洞察/YYYY-Wxx.md           ← 周洞察（本 skill 写；YYYY-Wxx = ISO 年-周号，如 2026-W35）
```

首次运行若 `咨询/洞察/` 目录不存在，先创建它。但若本周没有任何会谈，直接如实告知，**不要创建空洞察文件**。

## 归周规则（ISO 周，周一起）

- 用 ISO 8601 周：周一到周日为一周，算出目标周的 `YYYY-Wxx`（如 `2026-W35`）。
- 只聚合**该 ISO 周范围内**、且 `type: AI` 的会谈（用 frontmatter 的 `date` 判断，不按文件修改时间）。
- 若 cron 在周日晚触发，需明确「本周」指刚过去的这一自然周，别把边界上的会谈漏进或漏出。

## 工作流（按顺序执行）

### 第 1 步：定位目标周并列出候选会谈

1. 确认目标周（默认最近一个已结束的完整周；Jeff 点名某周则用那周）。
2. 算出该周 `YYYY-Wxx`。
3. 用 `search_files(target='files')` 列 `咨询/来访者/我/会谈/` 下的文件名，按 `YYYY-MM-DD` 前缀筛出该周日期范围内的候选。

### 第 2 步：按 frontmatter 过滤（type: AI）

- 对候选文件，只读 frontmatter（`read_file` 头部几行），拿到 `date / type / focus / mode`。
- 过滤出 `type: AI` 且 `date` 落在目标周内的会谈。`type: human` 一律跳过（只读不写）。
- 若目标周无任何 AI 会谈：如实告知「这一周没有 AI 会谈记录」，**不编造、不创建空洞察**。

### 第 3 步：读本周会谈全文（一周的量，可接受）

- 本周 AI 会谈通常 1–5 篇，量可控，可整篇读入（这是少数允许读多篇的场景——只读一周、有边界）。
- 提取每篇的：焦点（focus）、探索要点、命名的模式、尝试的实验、Takeaway、下次钩子（写回段）。

### 第 4 步：聚合与提炼

从多篇里找**反复出现的信号**，聚类成几条：

- 反复出现的主题 / 情绪 / 关系模式
- 本周进展（哪些议题推进了、哪些卡住）
- 反复出现的未完成钩子（下周需要接着带）
- 有效干预（这周哪些方法被证明有用）

### 第 5 步：写 洞察/YYYY-Wxx.md

用下方「周洞察模板」生成该周文件。若该周文件已存在（重跑/修正），覆盖写入，并在顶部注明生成时间。**所有判断句都用假设语气，并加「待你确认」标记。**

### 第 6 步：轻量更新 模式.md

- 仅当本周浮现了**之前 `模式.md` 里没有的新命名模式**，才在其末尾追加一条（注明来源日期 `(YYYY-Wxx)`）。
- 已有模式不重复追加。**不整体覆盖 `模式.md`**（那是长期积累文件，只追加）。

## 周洞察模板

```markdown

- 卡住了：

## 未完成钩子（下周带）
- （钩子，带最近日期）

## 有效干预
- （这周被证明有用的方法，带日期）

```

## 安全与隐私

- **路径安全**：只写 `咨询/洞察/YYYY-Wxx.md` 与 `咨询/来访者/我/模式.md`，两处都必须在 `咨询/` 内。用 realpath 前缀判断，禁止 `../` / symlink 越界。
- **绝不碰 type:human**：读取时可引用，写操作只针对 `洞察/` 与 `模式.md`。
- **隐私 sensitive**：涉及第三方（太太、父亲、孩子）保持概括，不写可识别细节。
- **结论标记假设**：洞察是「供 Jeff 回看和修改的草稿」，不是「心理评估报告」。所有推断都要 Jeff 确认后才可能沉淀进 档案/模式。

## Pitfalls

- **路径带空格**：vault 路径含空格（`Mobile Documents`），用 `read_file`/`search_files`/`write_file` 直接传绝对路径，别手工拼 shell 命令。
- **别把周洞察当定论**：status 必须是「假设」，否则会把推断固化进知识库，误导后续 counselor/recall。
- **归周边界**：严格按 ISO 周（周一起）和 frontmatter `date` 聚合，别用文件修改时间、别把周日晚的会谈算进下周。
- **无会谈就直说**：目标周没有 AI 会谈，告知即可，不要为了「有内容」而编造或拉入非本周记录。
- **不覆盖 模式.md**：它只追加不重写，防止把多年积累的模式文件整份冲掉。
